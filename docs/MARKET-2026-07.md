## 1. The 8 opportunities, ranked by the synthesizer

### 1.1 Provenance receipts: doctor identity check + per-response served-model logging ("know who actually answered") : effort M

- **Why now**: The Kimi K3 'I am Claude' scandal went from HN measurement (~15% of conversations) to a White House OSTP statement in under a week (July 17–23), making 'am I getting the model I pay for' the hottest trust question in the exact audience Lupin targets — and no router ships an answer.
- **Evidence**: K3 self-identifies as Claude (news.ycombinator.com/item?id=48965183; wccftech; gigazine July 23); silent model substitution is now formal attack/defense literature — single-token fingerprinting AUC 0.880 (arXiv 2607.10252, July 2026) and fingerprint-spoofing by 'Pro'-branded services (arXiv 2606.16100); OpenRouter now pins model+provider per conversation via cache fingerprints. Repo context: ROADMAP already sketches an M5 opt-in 'identity hint' (injection), but nothing verifies or records what upstream actually served.
- **Fit with Lupin**: This is the purest possible expression of ADR-2 ('the router that TELLS THE TRUTH'): the DOCTOR gains an identity scenario (requested model vs response `model` field vs self-report, recorded as evidence), and the proxy surfaces the served-model id per response WITHOUT persisting prompts — privacy rule intact. It pulls the existing M5 identity-hint idea forward from 'inject a hint' to 'verify and attest', compounding the doctor moat rather than adding a feature rivals can copy in a weekend.

### 1.2 Hybrid mode: Anthropic-subscription passthrough for Claude models + BYOK third-party routes beside it (revisit ADR-18) : effort M

- **Why now**: The July 20 Fable 5 repricing pushed Pro/Team Standard users onto $10/$50-per-MTok usage credits — the single biggest demand shock of the month — and Anthropic simultaneously documented the sanctioned hybrid path (base URL without credential keeps claude.ai OAuth active), so the window to be the compliance-clean hybrid router is open right now.
- **Evidence**: Fable 5 pricing saga June 30→July 20 (anthropic.com/news/redeploying-fable-5; techtimes; digitalapplied); subscription-through-gateway explicitly documented incl. the MUST-forward OAuth capability in anthropic-beta (code.claude.com/docs/en/llm-gateway#subscriptions-and-gateways); entitlement fail-closed pitfalls to avoid are live top issues (#79360 setup-token scope 403s, #78610 credits prompt with active sub); the OAuth-in-third-party-harness ban (April 4) killed the arbitrage alternative, leaving this the only clean fixed-cost combo. Repo conflict to resolve honestly: ADR-18 currently keeps `anthropic` as a debug null-test only.
- **Fit with Lupin**: Positions Lupin as the anti-arbitrage router: it never stores or touches subscription OAuth (structurally aligned with the April 4 policy), it just forwards headers verbatim — byte-faithful passthrough is already Lupin's discipline (ADR-7). The doctor extends naturally: verify the OAuth beta value survives, verify fast-mode/WebFetch bypass is documented, verify entitlement calls don't trip. Requires a deliberate ADR-18 amendment, which the DECISIONS.md process exists for.

### 1.3 Sonnet-5-era request compliance: map/strip thinking:{type:"adaptive"} + normalize the [1m] model-id suffix : effort S

- **Why now**: Since week 27 Claude Code sends adaptive thinking for ANY unrecognized model name — i.e. for every Lupin alias — so translate-mode upstreams will 400 on first contact for every new user until this lands; it is the difference between a working and a dead first run at launch.
- **Evidence**: Claude Code sends thinking:{"type":"adaptive"} for Claude 4.6+ AND unrecognized gateway aliases (code.claude.com/docs/en/llm-gateway-protocol feature pass-through table); model IDs now carry [1m] suffixes users set directly in /model and settings.json (code.claude.com/docs/en/model-config); competitor Paseo already shipped exactly this bug (getpaseo/paseo#1906); entitlement bug hypothesis #79337 shows even Anthropic trips on [1m] alias resolution. Repo check: SPEC-TRANSLATION has no rule for either today.
- **Fit with Lupin**: Two fixtures, per the fixture-first rule: adaptive-thinking on a non-Anthropic upstream (strip or map per dialect) and [1m]-suffix normalization in slot matching. Small, spec-driven, and it feeds the doctor a fresh check ('survives a Sonnet-5-era client') that the scoreboard can display — truth about compatibility, verified, dated.

### 1.4 Error-wording fidelity: preserve/emulate Anthropic error text so Claude Code's silent capability-degradation and fallbackModel chains keep working : effort M

- **Why now**: The gateway protocol reference (fetched July 23) reveals Claude Code's auto-recovery matches on upstream error WORDING — and with fallbackModel now chaining up to three models, Lupin's error bodies literally decide whether Claude Code self-heals or dies, which is the exact failure class ('400 / All target providers failed') driving users off claude-code-router this month.
- **Evidence**: Protocol docs: error bodies must pass unmodified; thinking-field/thinking-signature/mid-conversation-system-message rejections auto-recover only if wording survives (code.claude.com/docs/en/llm-gateway-protocol); fallbackModel accepts 3 fallbacks tried in order (whats-new week 24); CCR churn #1558 'All target providers failed' + 'highly unstable' complaints and back-to-back hotfixes 3.0.14/3.0.15 around SSE and upstream diagnostics (July 15–20); LiteLLM's open 'Content block not found' failure (BerriAI/litellm#13373) shows even the incumbent breaks here.
- **Fit with Lupin**: A SPEC-TRANSLATION error-mapping amendment plus fixtures: translate upstream OpenAI-compat errors into Anthropic-shaped bodies whose wording triggers the right client recovery. This is invisible-fidelity work no feature-list rival advertises — exactly the 'knows what works' moat — and each mapped error class becomes a doctor scenario with honest pass/fail.

### 1.6 Subagent-aware routing: honor per-subagent model overrides and x-claude-code-agent-id attribution, with a zero-takeover guarantee : effort M

- **Why now**: Subagents went background-by-default with a 200-spawn cap in the last month, so a router now sees many concurrent per-agent streams naming different models — and the incumbent is visibly broken here right now (#1564 'Subagent routing malfunction') while also angering users by hijacking global config (#1575, #1577).
- **Evidence**: Changelog June 22–July 21: subagents background by default, /fork backgrounds, per-subagent model override no longer reverts (v2.1.211), nested chains capped at 5; requests carry x-claude-code-session-id/agent-id/parent-agent-id for per-subagent cost attribution (llm-gateway-protocol); Agent(model:opus) permission matching makes model NAME a policy surface (whats-new week 25); CCR fresh issues #1564/#1575/#1577 (July 19–23); multi-agent sessions burn 4–7x tokens per slot-routing guides (fast.io subagents guide).
- **Fit with Lupin**: Slot mapping already exists; the extension is: a subagent request naming its own model must win over the slot default, agent-id headers pass through untouched, and Lupin never writes a byte into ~/.claude — the anti-CCR posture. The doctor gains a subagent scenario (spawn a background agent with an override, assert the right upstream got it), and per-agent-id token attribution in status gives cost truth without persisting any prompt content.

### 1.8 Cache-transparency receipts: doctor measures actual cache-read tokens across a resumed session through Lupin : effort S

- **Why now**: Users are now MITM-ing their own CLI after a reverse-engineering post showed cache breakage silently inflates costs 10–20x, and a dedicated community proxy (claude-code-cache-fix) exists just to stop header-churn cache busting — 'provably cache-transparent' is a claim buyers are actively looking to verify this month.
- **Evidence**: r/ClaudeAI Ghidra+MITM analysis, Anthropic-acknowledged regression GH #40524, claude-code-cache-fix repo and Medium post on 10–20x cost (June–July 2026); attribution block is cache-stable-per-conversation since v2.1.181 and must stay first in the system array (llm-gateway-protocol). Repo check: doctor already preflights cache_control acceptance on passthrough profiles and test/cache-stability.test.ts covers prefix stability — the missing piece is measured cache-HIT evidence end-to-end.
- **Fit with Lupin**: An incremental doctor scenario on existing machinery: run a resumed headless session through Lupin and assert usage.cache_read_input_tokens stays nonzero (byte-faithful passthrough means Lupin should pass trivially — which is the point: prove it, don't claim it). The published number ('N% cache hits preserved, measured DATE') slots straight onto the public scoreboard and directly counters the category's paranoia.

## 2. Decisions taken afterwards (2026-07-23, with the user)

1. **Cache work APPROVED** (it derives from opportunity 1.8 plus the audit): (a) *cache receipts*, a doctor scenario that
   measures the real `cache_read_input_tokens` over a resumed session through Lupin (prove the transparency, do not
   declare it; the number goes on the scoreboard); (b) *the fix* for `prompt_tokens_details.cached_tokens` never being
   mapped in translate (already on record in the audit, a cost-visibility gap); (c) *optional*: a cache-bust detector in
   the tap, comparing prefixes in memory, never persisted, to diagnose "this request broke the cache".
   Priority: (a) and (b) before launch (effort S); (c) to be assessed. **NO Rust**: the cache lives on the provider and
   the proxy buffers nothing, so a native toolchain would violate rule 6 and make the packaging blocker worse.
2. **The `lupin top` TUI** is already recorded as the shape of backlog #8 (commit `a14393c`): it will be the surface for
   per-agent attribution (opportunity 1.6) and plan cost mode (opportunity 1.7).
3. **Sonnet-5-era compliance (opportunity 1.3) recognized as a near launch blocker**: `thinking: {"type":"adaptive"}`
   sent on every unrecognized alias plus the `[1m]` suffix, since without a mapping translate answers 400 on the first run.
